Common UI란

Common UI는 언리얼 기본 UMG를 확장한 게임용 UI 플러그인이다.

콘솔·게임패드 지원, 크로스플랫폼 입력(터치·마우스·게임패드), 다양한 플랫폼에서 UI를 편하게 쓸수있음.
(key값이나 플랫폼마다 설정가능. 가장큰장점)
Lyra도 CommonUI를 기반으로 Widget을 구성한것으로 알고 있다.

소개하는 컴포넌트는 크게 둘이다.

  • CommonActivatableWidget
    — 위젯인데 다양한 컴포넌트들을 활용해 편리한 기능을 사용할 수 있습니다
    (ex 위젯이 종료될때 Fade애니메이션을 지원합니다/ StackWidget을 사용해 UI를 차례대로 끌 수 있습니다.)

  • CommonButtonBase
    — 버튼을 위젯으로 만든것 입니다
    — 다양한 상태를 지원합니다 ( Hovered같은 상태말고 Selected상태를 지원 선택됨 상태를 지원합니다 )
01

CommonActivatableWidget

CommonUI 전용 위젯이며, 스택은 별도의 CommonWidget이 관리합니다

CommonActivatableWidget은 On Activate, On DeActivate노드를 가지는데 Construct와 비슷합니다.
중요한 건, 이 위젯 자체는 스택을 갖지 않는다는 점이다.
스택 기능은 별도의 CommonActivatableWidgetStack (Widget)이 담당한다.



Widget vs Stack

CommonActivatableWidget = 스택에 담기는 "한 장"

CommonActivatableWidgetStack = 그 장들을 쌓는 "통"

접시(Widget) 한 장은 자기가 몇 번째로 쌓였는지 모르고, 트레이(Stack)가 순서를 관리한다.

AddToViewport를 하지않습니다. PushWidget함수 하나로 끝이 납니다

StackWidget의 내장 함수로 화면을 쌓고 뺀다.

  • Push Widget — 스택에 위젯을 쌓음 (새 화면 열기)
  • Remove Widget — 스택에서 빼냄 (화면 닫기)


Cropout에서는 Main Stack이 있었고, 일시정지·건설 메뉴 등을 여기에 Push했다.

Main_HUD ← 기존의 MainHUD
Root_CAW StackWidget의 Root(파괴불가)
PopShop_CAW PushWidget으로 생성

위젯을 연 순서대로 닫힐때도 역순으로 차례대로 닫힘.

Push / Remove의 생명주기

동작결과
Push새 위젯이 위에 쌓임. 아래 위젯은 안 보이고 비활성되지만 ref 유지
Remove (Pop)위젯이 Destruct되고 ref 사라짐 (파괴)
주의

Push는 위젯을 새로 CreateWidget으로 생성하고 Pop할 때 파괴하는 게 기본이다. Visibility만 토글하는 게 아니다. 그래서 화면을 열 때마다 On Activated에서 초기화·바인딩을 다시 해줘야 한다. (단, Root Content는 바닥에 항상 유지되어 파괴되지 않는다.)

Deactivate ≠ Destruct

  • 위에 다른 위젯이 Push되어 밀림 → Deactivate만 됨 (살아있음)
  • 스택에서 Pop되어 빠짐 → Deactivate + Destruct (파괴)

그래서 Construct에서 건 바인딩은 Deactivate로는 안 풀린다. 밀린 상태에서도 확실히 정리하려면 On Activated에서 bind → On Deactivated에서 unbind로 짝을 맞추는 게 안전하다.

닫힐 때 고급스러운 Fade 애니메이션을 자동 제공한다 (StackWidget이 제공)



위젯이 Push/Remove될 때 부드러운 fade 전환이 자동으로 붙는다.
단, 정확히는 위젯 자체 기능이 아니라 StackWIdget의 Transition 설정 덕분이다.

Main Stack · Transition
Transition TypeFade Only
Transition Duration0.4
Transition CurveLinear
02

CommonButtonBase

일반 UMG의 Button을 대체하는 강화된 버튼. 게임패드 네비게이션, 선택 상태, 스타일 관리를 기본 지원한다.
언리얼이 좋아하는 기능과 역할의 분리개념으로 버튼위젯을 따로, Style따로, Text따로 분리를 해놨다

버튼Border부터 Style, Text 해제쇼

그래서 스타일이 계층으로 분리되어 있고, 필수적으로 필요한건 Style정도이다



소리도 지정할 수 있음. 근데 Style에서 보통 지정함


  • CommonButtonStyle — 버튼의 외형 (상태별 브러시/머티리얼)




    • Style에서 커스텀크기조정가능 = sizebox안써도됨, TextStyle적용(TextStyle만들어야함), 소리를 여기서 지정



    여기가 정말 중요!! 머티리얼을 잘 만들어야 고급진 버튼 생성가능 !!

  • CommonTextStyle — 버튼 안 텍스트의 외형 (폰트·색)
Style Hierarchy
CommonTextStyle      폰트·색 — 맨 아래
      ↑ 참조
CommonButtonStyle    상태별 외형 + 텍스트 스타일 참조
      ↑ 연결
CommonButtonBase     동작 + 스타일 연결

스타일 지정 없이는 브러시에서 버튼 색이 변하지 않는다

함정

CommonButtonStyle을 지정하지 않으면, 버튼의 상태별 색(Normal / Hovered / Pressed)이 브러시에서 변화하지 않는다. 일반 버튼처럼 색을 직접 넣는 게 아니라, 스타일 에셋을 통해 상태별 외형을 관리하는 구조이기 때문이다.

CommonButtonStyle에 머티리얼을 지정해 버튼에 적용한다

버튼의 각 상태(Normal, Hovered, Pressed 등)에 대한 머티리얼(또는 브러시)을 CommonButtonStyle 에셋에 지정하고, 그 스타일을 버튼의 Style 속성에 연결해야 실제 외형이 적용된다.

스타일을 에셋으로 분리하는 이유는 재사용이다. 스타일 하나를 여러 버튼이 공유하면, 나중에 디자인을 바꿀 때 스타일 하나만 수정해도 전부 반영된다.

Selected 기능이 있다

일반 버튼은 "눌림"만 있지만, CommonButtonBase는 "선택됨(Selected)" 상태를 가진다. 탭 메뉴나 토글 버튼을 만들 때 유용하다. 예를 들어 카테고리 탭 3개 중 하나를 누르면 그것만 Selected로 강조.

발견된 이슈 — 포커스 문제

가장 많이 헤맨 부분. Common UI는 자체 입력 라우팅과 포커스 시스템을 가지는데, 이게 게임 입력과 충돌할 수 있다.

Symptom · 증상
  • UI 위젯이 떠 있으면 첫 클릭이 안 먹고 두 번 연달아 클릭해야 게임 IA가 반응
  • 마우스 이동이 게임 액션으로 잘 안 감
  • UI를 모두 끄면 첫 클릭부터 정상 → Common UI가 첫 입력을 포커스로 흡수
Cropout은 왜 한 번에 됐나

Cropout은 건설 위젯 On Activated에서 Set Input Mode UI Only + Disable Input을 걸어 게임 입력과 UI 입력을 경쟁시키지 않았다. 모든 입력이 UI로만 가니 첫 클릭부터 깔끔했던 것. 반면 Game and UI로 둘을 동시에 살리면 포커스 경쟁이 생긴다.
